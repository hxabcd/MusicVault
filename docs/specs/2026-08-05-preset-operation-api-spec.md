# Preset 操作 API 与执行语义 Spec

状态：已完成（2026-08-12）
范围：本次工程重构

## Problem Statement

preset 需要足够自由来支持未来的播放器和设备目标，但如果脚本直接操作内部文件、数据库和 Service，就会失去统一的 dry-run、错误记录、重试和测试能力。

因此需要同时提供标准操作和明确的自定义操作入口。

## Solution

标准操作通过公开 preset context 提供，例如：

- 获取曲目和媒体资产；
- 创建链接；
- 复制文件；
- 写入文本或歌词；
- 写入目标元数据；
- 请求媒体规格；
- 调用目标 adapter。

脚本可以登记自定义操作。自定义操作允许任意 Python 逻辑、外部程序或设备调用，但必须通过 context 登记，以便系统获得操作名称、输入、输出和结果。

脚本不得直接依赖内部数据库、内部 Service 或未经公开的全局对象。

统一执行语义如下：

- dry-run 可以展示标准操作和已登记的自定义操作；
- 幂等性、可重试性和是否支持 dry-run 由操作声明；
- 自定义操作不强制保证回滚；
- 单项失败继续处理其他项；
- preset 初始化失败终止当前 preset；
- 最终结果通过结构化对象返回，并由 CLI 转换为输出和退出码。

## User Stories

1. 作为 preset 作者，我希望通过标准 API 创建链接和复制文件。
2. 作为 preset 作者，我希望通过标准 API 写入元数据和歌词。
3. 作为 preset 作者，我希望调用统一的媒体资源解析能力。
4. 作为 preset 作者，我希望执行标准 API 无法覆盖的自定义 Python 逻辑。
5. 作为项目维护者，我希望所有自定义操作都能显示在 dry-run 计划中。
6. 作为项目维护者，我希望自定义操作的输入和输出可被记录。
7. 作为用户，我希望一首歌曲失败不会阻塞其他歌曲。
8. 作为用户，我希望 preset 初始化失败时不会继续执行不完整的目标同步。
9. 作为项目维护者，我希望能区分可重试错误和不可重试错误。
10. 作为用户，我希望任务失败时 CLI 返回非零退出码。
11. 作为项目维护者，我希望脚本不能通过私有对象绕过状态管理。
12. 作为测试作者，我希望可以使用 fake context 测试 preset 行为。
13. 作为用户，我希望标准操作拥有一致的文件冲突行为。

## Implementation Decisions

- context 是 preset 脚本访问系统能力的唯一推荐入口。
- 标准操作由系统统一执行并返回结构化结果。
- 自定义操作通过明确的 custom operation API 登记。
- 自定义操作可以执行任意可信 Python 逻辑，但不承诺事务回滚。
- 每个操作声明是否幂等、可重试和支持 dry-run。
- 操作结果至少包含状态、错误信息和受影响对象。
- 失败分为全局准备失败、单项失败、目标失败和最终整理失败。
- 单项失败不影响其他项；当前 preset 的最终状态为失败。
- 一个 preset 失败不影响其他 preset；整体 CLI 结果为非零。
- 只有显式管理的操作才允许执行清理或删除。

## Testing Decisions

- 测试标准 API 的外部结果，不测试 context 内部实现。
- 测试自定义操作被登记、执行并记录结果。
- 测试 dry-run 不产生文件系统或目标端副作用。
- 测试幂等操作重复执行不会产生重复目标。
- 测试单项失败会继续处理后续项。
- 测试 prepare 失败不会调用后续操作。
- 测试错误分类会产生正确的最终退出码。
- 使用 fake context 和临时文件系统作为主要测试接缝。

## Out of Scope

- 代码沙箱。
- 自动回滚所有自定义操作。
- 自定义操作的跨进程分布式执行。
- 运行时自动安装脚本依赖。
- 目标端双向冲突合并。

## Further Notes

“通过 API 进行实际操作”是标准路径；“允许自定义操作”是显式逃生舱。两者并不冲突，但自定义操作必须接受更弱的可恢复性保证。
