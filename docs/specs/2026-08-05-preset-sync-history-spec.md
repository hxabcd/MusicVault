# Preset 同步历史 Spec

状态：后续扩展
范围：不纳入本次改造

## Problem Statement

未来需要追踪每个 preset 每次 sync 的执行情况，以便了解哪些目标成功、失败、跳过或部分完成。但如果长期保存每首曲目的所有历史，数据库会快速膨胀，查询和清理也会变复杂。

## Solution

每次整体 sync 产生一个运行记录，每个执行的 preset 产生一个聚合记录。只保存每个 preset 最近若干次运行，保留数量由全局配置控制。

建议记录：

- sync run ID；
- preset 名称；
- preset 脚本摘要；
- preset API 版本；
- source snapshot hash；
- 开始和结束时间；
- 状态；
- 成功、失败、跳过数量；
- 错误摘要；
- 目标标识。

本功能不保存完整的单曲历史。必要时只在保留的 preset run 中保存有限的失败摘要或操作统计。

保留策略仅使用全局配置，例如最近保留 5 次。暂不提供每个 preset 单独覆盖。

## User Stories

1. 作为用户，我希望查看最近几次整体 sync 是否成功。
2. 作为用户，我希望知道每个 preset 是否成功完成。
3. 作为用户，我希望看到某个 preset 成功、失败和跳过的数量。
4. 作为用户，我希望看到失败的简短原因。
5. 作为项目维护者，我希望运行记录关联 source snapshot 和 preset 版本。
6. 作为项目维护者，我希望历史数量由一个全局配置控制。
7. 作为用户，我希望旧历史自动清理，不需要手动删除数据库记录。
8. 作为项目维护者，我希望保留策略不会删除当前运行或未完成运行。
9. 作为用户，我希望一个 preset 失败时仍能看到其他 preset 的结果。
10. 作为项目维护者，我希望数据库不会因逐曲目历史无限增长。
11. 作为测试作者，我希望可以验证保留数量、失败状态和清理边界。

## Implementation Decisions

- 使用 `sync_runs` 表记录一次整体同步。
- 使用 `preset_runs` 表记录每个 preset 的聚合结果。
- 当前不设计完整 `preset_run_items` 历史表。
- 历史保留数量只由全局配置控制。
- 默认所有启用 preset 的执行结果都进入同一个 sync run。
- 单个 preset 失败不会覆盖其他 preset 的结果。
- 运行记录包含 preset 脚本 hash、API 版本和 source snapshot hash。
- 保留清理由系统统一执行，不由 preset 脚本自行删除。
- 未完成运行需要具有明确状态，不能被误清理。

## Testing Decisions

- 测试一次 sync 生成整体记录和多个 preset 记录。
- 测试单个 preset 失败时其他 preset 仍被记录。
- 测试全局保留数量删除最旧记录。
- 测试保留数量为 0、1 和较大值的边界。
- 测试当前运行和未完成运行不会被清理。
- 测试脚本 hash、API 版本和 snapshot hash 被正确保存。
- 测试历史记录查询只依赖外部可见状态，不依赖具体 SQL 排列。

## Out of Scope

- 本次工程重构不实现同步历史。
- 单曲级长期历史。
- 历史趋势图和复杂报表。
- 远程监控和通知。
- 每个 preset 单独配置保留数量。

## Further Notes

该功能依赖 TargetSynchronizer 产生结构化运行结果，因此本次应保留运行上下文和结果对象，但不实现历史持久化与清理。
